# pcagent Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A LangGraph agent for P&C insurance where every tool call is allowed, sent to a person, or denied by rules plus Jev, with approvals that survive restarts. It ships with an API, a CLI, evals and traces for a LinkedIn demo.

**Architecture:** A custom StateGraph with four nodes: `agent`, `policy`, `approval` (`interrupt()`) and `tools`. Tools come from MCP servers through our own bridge on `mcp` 2.x, and the model through LiteLLM. State is checkpointed to Postgres, or kept in memory for tests. FastAPI exposes threads, runs and approvals, and a thin httpx CLI drives the demo.

**Tech Stack:** Python 3.12, uv, langgraph 1.2, langgraph-checkpoint-postgres 3.2, langchain-core 1.8, langchain-litellm 0.11, litellm 1.110, mcp 2.3, typesafe-sdk 0.7.5, FastAPI, pydantic-settings, pytest + pytest-asyncio, Langfuse.

**Spec:** `docs/superpowers/specs/2026-11-22-pcagent-design.md`

## Global Constraints

- Python `>=3.12`, managed with `uv`. Run tests with `uv run pytest`.
- Do **not** add `langchain-mcp-adapters`. It needs `mcp<2`, and `litellm` needs `mcp>=2.3`.
- MCP 2.x field names are snake_case: `tool.input_schema`, `result.is_error`,
  `tool.annotations.read_only_hint` and `tool.annotations.destructive_hint`.
- Default model: `anthropic/claude-opus-5-5`. The local model for the injection beat is `ollama/qwen3:8b`.
- Jev model: `jev-latest`, from `TYPESAFE_MODEL`. A Jev Score is the expected level index, from 0 to n-1.
- Policy must fail closed. If Jev errors or isn't configured, the call is `require_approval`, never `allow`.
- `bind_policy_change` is always `deny`.
- Demo and manual runs use the deployed PAS at `https://gwmcp.ashenlabs.ca/mcp`, over Streamable HTTP. It holds shared, persistent state.
- Automated tests never call the deployed server. They use the local mock:
  `uv run --project ../gwmcp python server.py`, with `cwd=../gwmcp` and `GW_MOCK=true`.
- Tests marked `live` need network and keys. They are excluded by default (`addopts = "-m 'not live'"`).
- Each task ends with a note in `docs/layers/NN-<layer>.md` of at most about 40 lines,
  answering what the layer does, why it was built that way, and what broke or
  surprised us. That note is part of the task.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Two tool calls in one turn, where one needs approval and one doesn't.** Every call waits for the approval, then the allowed ones run. Each call gets exactly one ToolMessage, in the same order as the calls (Task 3).
2. **A new message sent to a thread that is waiting for approval.** The API returns 409 with the pending calls, instead of corrupting the history with unanswered tool calls (Task 5).
3. **An approval payload that leaves out a call or names an unknown id.** A missing call counts as rejected, an unknown id is ignored, and nothing crashes. Resuming a thread that isn't paused returns 409 (Tasks 3 and 5).
4. **An MCP server that fails to start,** for example because the `gwmcp` path is wrong. Startup fails with a `ToolboxError` that names the server (Task 2).
5. **A tool that raises, or an MCP result with `is_error`.** It becomes an error ToolMessage and the run continues to a model reply (Task 3).

### Task 3: Model gateway and the graph

**Files:**
- Create: `src/pcagent/gateway.py`, `src/pcagent/graph.py`, `tests/fakes.py`, `tests/test_graph.py`,

  - `make_model(model: str) -> BaseChatModel`, which returns `ChatLiteLLM(model=model)`.

### Task 5: Runs helper and the FastAPI API

**Files:**

**Interfaces:**
- Produces, in `runs.py`:
  - `serialize(msg) -> dict` with the keys `type, content`, plus `tool_calls`, `tool_call_id` and `status` when present.
  - `async run_turn(graph, thread_id: str, message: str, callbacks: list | None = None) -> dict`
  - `async resume(graph, thread_id: str, decisions: dict, callbacks: list | None = None) -> dict`
  - `async thread_view(graph, thread_id) -> dict` with the keys `thread_id, messages, pending, audit`.
  - Run result keys: `status` (`"completed"` or `"awaiting_approval"`), `messages` (only those added by this call), `pending` (decisions still waiting, possibly empty) and `decisions` (audit records added by this call).
  - `class ThreadBusy(Exception)`, raised by `run_turn` when the thread is awaiting approval. `class NotAwaiting(Exception)`, raised by `resume` when it isn't.
- Produces, in `runtime.py`: `default_runtime(settings) -> AsyncContextManager[CompiledStateGraph]`. It opens the `MCPToolbox` and checkpointer, then builds `PolicyEngine(Policy.load(settings.policy_path), JevJudge())`, then `make_model(settings.model)`, then `build_graph`.
- Produces, in `api.py`: `create_app(runtime=None) -> FastAPI`. `runtime` is a zero-argument callable that returns the async context manager above, and it defaults to `lambda: default_runtime(get_settings())`. The lifespan stores the graph on `app.state.graph`. The routes:

  - `POST /threads/{id}/runs` with body `{"message": str}` returns the run result. `ThreadBusy` gives 409 with `{"detail": "awaiting approval", "pending": [...]}`.
  - `POST /threads/{id}/approvals` with body `{"decisions": {id: {"approved": bool, "note": str = ""}}}` returns the run result. `NotAwaiting` gives 409.
  - `GET /threads/{id}` returns `thread_view`. A thread with no checkpoint gives 404.
  - `GET /health` returns `{"ok": true}`.
